### 3 Pola Penyakit Proses di Linux & Cara Nemuinya

Di production, proses bermasalah itu biasanya kena salah satu dari 3 penyakit ini:

```
                  [ PROSES BERMASALAH ]
                            │
       ┌────────────────────┼────────────────────┐
       ▼                    ▼                    ▼
 [ 1. Maruk Resource ] [ 2. Mati Suri (D/Z) ] [ 3. Freeze / Gak Maju ]
  CPU 100% / RAM Leak   Stuck I/O / Zombie      Nunggu Socket / Lock
```

---

#### 1. Penyakit 1: Maruk CPU / RAM (Infinite Loop atau Memory Leak)
* **Gejalanya:** Laptop/server kipasnya kenceng, sistem mendadak berat.
* **Cara Nemuinnya (Gak usah nyari manual di `ps aux`):**
  1. Buka `top` di terminal.
  2. Tekan tombol **`P`** (Shift + P) di keyboard → Ini langsung **mengurutkan proses paling rakus CPU di urutan paling atas.**
  3. Tekan tombol **`M`** (Shift + M) di keyboard → Ini langsung **mengurutkan proses paling rakus RAM di urutan paling atas.**
  4. Lu langsung liat PID dan nama program biang keroknya di baris nomor 1.

---

#### 2. Penyakit 2: Mati Suri (State `D` atau `Z`)
* **Gejalanya:** Proses gak bisa di-`kill` bahkan pake `kill -9`.
* **Penyebab:** Biasanya dia lagi minta baca harddisk tapi harddisk-nya bad sector, atau koneksi NFS-nya putus (Kernel nahan proses itu di antrean I/O).
* **Cara Nemuinnya di `ps aux`:**
  Perhatikan kolom **`STAT`** (Status) di `ps aux`:
  * `R` (*Running*): Sehat, lagi dieksekusi CPU.
  * `S` (*Sleeping*): Normal, lagi nunggu giliran atau nunggu timer/event.
  * `D` (*Uninterruptible Sleep*): **BAHAYA.** Lagi macet di level hardware I/O disk.
  * `Z` (*Zombie*): Prosesnya udah mati, tapi proses induknya (parent) lupa bersihin.

Cara cari yang kena status `D` langsung pake satu baris:
```bash
ps aux | awk '$8 ~ /D/'
```

---

#### 3. Penyakit 3: Freeze Nungguin Jaringan (Kasus `scraper.py` Lu)
Ini kasus paling sering terjadi pas lu koding Python / Scraper / API:
* **Gejalanya:** CPU-nya 0.0% (gak makan resource), RAM normal, statusnya `S` (Sleeping), tapi **script-nya gak selesai-selesai.**
* **Kenapa?** Karena script Python lu lagi nembak website (misal Shopee), tapi koneksi internetnya nge-drop/gantung, dan di kodingan Python lu **gak pasang `timeout`**. Dia bakal nungguin paket data dari server target sampai kiamat.

**Langkah Investigasi Kasus Ini:**

1. **Cari PID script Python lu langsung:**
   ```bash
   pgrep -a python
   # atau
   ps aux | grep scraper.py
   ```
2. **Cek apakah dia lagi nahan koneksi socket jaringan yang gantung:**
   ```bash
   ss -tp | grep <PID_script_lu>
   # atau
   lsof -p <PID_script_lu> -i
   ```
   *(Lu bakal liat IP mana dan port berapa yang lagi bikin script lu nyangkut).*

3. **Intip isi kepalanya (Senjata Rahasia Senior: `strace`):**
   ```bash
   sudo strace -p <PID_script_lu>
   ```
   * Perintah `strace` bakal nunjukin secara *live* System Call apa yang lagi diminta script lu ke Kernel Linux.
   * Kalau script lu freeze di jaringan, lu bakal liat dia nyangkut di command kernel: `recvfrom(...)` atau `poll(...)` tanpa henti.

### Kesimpulan Mental Model:
* Kalau server lemot → Buka `top` lalu pencet `Shift+P` (CPU) atau `Shift+M` (RAM).
* Kalau tau nama script-nya (misal `scraper.py`) tapi gak tau PID-nya → Pake `pgrep -a python` atau `ps aux | grep scraper.py`.
* Kalau script diem tanpa error → Cek koneksi socket-nya pake `lsof -p <PID> -i` atau intip pake `strace -p <PID>`.
