### 🧪 LAB DAY 3: Berburu & Membunuh Process (Process Investigation)

**Skenario Nyata DevOps:**  
Script Python scraper atau service aplikasi lu tiba-tiba nge-hang (freeze) atau makan RAM/CPU sampai 100%. Lu gak bisa nungguin dia restart sendiri. Tugas lu: cari siapa pelakunya, dapatkan **PID (Process ID)**-nya, lalu matikan prosesnya secara terkendali.

---

#### 1. Konsep Wajib: Apa itu PID & `ps aux`?
Setiap program atau script yang jalan di Linux bakal dikasih KTP unik oleh Kernel, namanya **PID (Process ID)**.

Ketik ini di terminal:
```bash
ps aux
```
* **Bedah Flag `aux`:**
  * `a` → Tampilkan proses milik semua user (bukan cuma user lu).
  * `u` → Tampilkan detail pemakaian resource (%CPU, %MEM, waktu start, user pemilik).
  * `x` → Tampilkan juga proses yang jalan di background (yang gak nempel ke terminal).

Karena output `ps aux` ada ratusan baris, kita gabungin sama ilmu Day 2 (Pipa + Grep):
```bash
ps aux | grep bash
```

---

#### 2. Lab Hands-on: Bikin "Proses Kelinci Percobaan" & Buru PID-nya

Biar lu ngerasain langsung proses berburu ini, kita bikin program tidur di background:

**Langkah 1: Jalankan proses palsu di background**
```bash
sleep 1000 &
```
*(Tanda `&` di ujung perintah artinya: "Jalankan perintah ini di background, jangan bikin terminal gue nge-lock").*

**Langkah 2: Cari PID si `sleep` tadi**
```bash
ps aux | grep sleep
```
Perhatikan outputnya, ada baris yang mirip kayak gini:
```text
edriel   12345  0.0  0.0   5432   980 pts/0    S    10:30   0:00 sleep 1000
```
Angka kedua (misal: `12345`) itu adalah **PID**-nya.

---

#### 3. Cara Mematikan Process: `kill` vs `kill -9`

Di Linux, kita gak langsung bantai proses. Kita kirim sinyal (*Signal*):

1. **`kill <PID>` (Sinyal Sopan / SIGTERM - Signal 15):**
   * *Artinya:* "Woi proses, tolong beres-beres kerjaan lu, simpan data, terus tutup pintu baik-baik."
   * Coba matikan proses `sleep` lu tadi pake PID yang lu dapet:
     ```bash
     kill <ganti_dengan_PID_sleep_lu>
     ```
   * Cek lagi pake `ps aux | grep sleep` — apakah prosesnya udah hilang?

2. **`kill -9 <PID>` (Sinyal Headshot / SIGKILL - Signal 9):**
   * *Artinya:* "Kernel, jangan kasih ampun, langsung cabut nyawa proses ini sekarang juga detik ini!" (Dipake kalau aplikasinya bener-bener nge-hang total dan gak respon sama `kill` biasa).

---

#### 4. Intip Resource Live: `top`
Ketik:
```bash
top
```
* Perhatikan baris paling atas: **load average**, **%Cpu(s)**, dan **MiB Mem**.
* Buat keluar dari `top`, tekan tombol **`q`**.
